# ТехноРемонт — сервис ремонта компьютерной техники

Лабораторная работа «Контейнеризация многокомпонентных приложений с помощью Docker Compose».

| Параметр варианта | Реализация |
|---|---|
| Тематика Web-сервиса | Ремонт техники (компьютерная техника: ноутбуки, ПК, моноблоки, мониторы, принтеры) |
| Функция Web-сервиса | Расчёт ориентировочной стоимости ремонта по симптомам |
| Данные для БД | Заявки на обслуживание (клиенты, устройства, симптомы, оценка, статус) |

## Архитектура

```
 Браузер ──► frontend (nginx, :8080)
                │  /api/*
                ▼
            backend (Flask REST API, :8000) ──► db (PostgreSQL 16, :5432)
                │
                ▼
            web-service (Flask, расчёт стоимости, :8001)
```

Все 4 контейнера находятся в одной мостовой сети `repair-net` и обращаются друг к другу по именам сервисов.

| Сервис | Технологии | Назначение |
|---|---|---|
| `frontend` | HTML, CSS, JavaScript, nginx | Интерфейс; nginx раздаёт статику и проксирует `/api` в backend |
| `backend` | Python 3.12, Flask, psycopg 3, gunicorn | REST API: CRUD заявок в БД, статистика, интеграция с Web-сервисом |
| `db` | PostgreSQL 16 | Таблицы `clients`, `service_requests`, `device_types`, `request_statuses`, представление `v_requests`; первичные данные из `db/init.sql` |
| `web-service` | Python 3.12, Flask, gunicorn | Микросервис расчёта: симптомы → вероятные работы → диапазон цены и срок |

### Кнопки интерфейса

1. **«Загрузить заявки из БД»**: запрос данных из PostgreSQL через backend (таблица заявок + статистика).
2. **«Рассчитать стоимость»**: запрос к Web-сервису через backend (перечень работ, цена «от–до», срок).
3. **«Оформить заявку и сохранить в БД»**: добавление записи (backend получает оценку от Web-сервиса и сохраняет заявку).
4. Смена статуса заявки (UPDATE) и удаление (DELETE) прямо в таблице.

## Запуск

Требуется установленный Docker с Docker Compose (Docker Desktop для Windows и macOS).

```bash
docker compose up -d --build
```

После запуска откройте http://localhost:8080

Остановка: `docker compose down`. Полный сброс вместе с данными БД: `docker compose down -v`.

Порты и параметры подключения к БД можно изменить в файле `.env` (образец: `.env.example`).

## REST API (backend, http://localhost:8000)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/health` | Состояние backend, БД и Web-сервиса |
| GET | `/api/requests?status=&q=` | Список заявок (фильтр по статусу, поиск) |
| GET | `/api/requests/{id}` | Одна заявка |
| POST | `/api/requests` | Создать заявку (с автоматическим расчётом стоимости) |
| PATCH | `/api/requests/{id}` | Изменить `status`, `final_cost`, `master_comment` |
| DELETE | `/api/requests/{id}` | Удалить заявку |
| GET | `/api/stats` | Статистика по заявкам |
| GET | `/api/statuses` | Справочник статусов |
| GET | `/api/catalog` | Справочник устройств и симптомов (из Web-сервиса) |
| POST | `/api/estimate` | Расчёт стоимости (через Web-сервис) |

## Web-сервис (http://localhost:8001)

* `GET /health`
* `GET /api/v1/catalog`: типы устройств, симптомы, варианты срочности
* `POST /api/v1/estimate`: расчёт

```json
{ "device_type": "laptop", "symptoms": ["overheating", "slow"], "urgency": "normal" }
```

Алгоритм: каждый симптом связан с возможными работами и их вероятностями. Если работа следует из нескольких симптомов, вероятности объединяются по формуле `P = 1 − П(1 − pᵢ)`. Основные работы (самая вероятная для каждого симптома и все с P ≥ 60 %) формируют нижнюю границу цены, а возможные (P ≥ 25 %) добавляются к верхней. Итог умножается на коэффициент типа устройства и коэффициент срочности.
